# Пошаговая инструкция «под ключ» — от нуля до работающего сайта

Эта инструкция написана для человека, который **никогда раньше не запускал
сайт на Node.js**. Можно идти по пунктам сверху вниз, ничего не пропуская.
Все команды копируются и вставляются в Терминал — никакого программирования
от вас не требуется.

Если что-то пойдёт не так — смотрите раздел **«Если что-то не работает»** в
самом конце.

---

## ШАГ 1. Установить Node.js (если ещё не установлен)

Node.js — это среда, в которой работает сайт. Один раз ставится, дальше
никогда не трогается.

1. Откройте сайт <https://nodejs.org/>.
2. Скачайте версию с пометкой **LTS** (зелёная большая кнопка).
3. Запустите скачанный `.pkg`-файл и нажимайте «Далее / Продолжить», пока
   установка не завершится.
4. Откройте **Терминал** (Cmd + Пробел → наберите «Терминал» → Enter) и
   проверьте, что всё установилось — в Терминале выполните:

   ```bash
   node --version
   npm --version
   ```

   Должны увидеть что-то вроде `v20.18.0` и `10.x.x`. Если видите —
   отлично, идём дальше.

> Git у вас уже есть — он шёл с macOS. Проверка: `git --version` в Терминале
> покажет что-то вроде `git version 2.x.x`.

## ШАГ 2. Открыть папку проекта в Терминале

Все следующие команды нужно выполнять **внутри папки проекта**. Чтобы туда
попасть, выполните в Терминале:

```bash
cd "/Users/amattolkocokov/Documents/Claude/Projects/Проект ЦБ"
```

Проверьте, что вы там:

```bash
pwd
```

Должно показать: `/Users/amattolkocokov/Documents/Claude/Projects/Проект ЦБ`.

> Можно проще: откройте Finder, найдите папку «Проект ЦБ», нажмите на неё
> правой кнопкой → «Службы» → «Открыть Терминал в текущей папке».

---

## ШАГ 3. Удалить служебные папки из песочницы (один раз)

В папке остались два «мусорных» каталога после первичной сборки. Они не
нужны и просто занимают место. Удалить безопасно — в коде они не
используются и в `.gitignore` уже прописаны:

```bash
rm -rf .node_modules_old .package-lock.json.old
rm -rf .git.broken_*
```

Если каких-то из них уже нет — `rm` напишет «No such file or directory», и
это нормально.

---

## ШАГ 4. Установить зависимости проекта

Это нужно сделать **один раз** при первом запуске. Команда скачает все
библиотеки, которые использует сайт (это около 300 пакетов, 200–400 МБ).

```bash
npm install
```

Это займёт 1–3 минуты. В конце вы увидите примерно:

```
added 320 packages in 90s
```

> Если в процессе появятся предупреждения с пометкой `WARN` (жёлтые) —
> игнорируйте. Опасны только ошибки `ERROR` (красные).

---

## ШАГ 5. Создать базу данных

База данных хранится в обычном файле `prisma/dev.db` прямо в папке
проекта. Чтобы её создать с правильной структурой, выполните:

```bash
npx prisma db push
```

Должны увидеть строку `Your database is now in sync with your Prisma schema.`
Если она есть — база создана.

---

## ШАГ 6. Создать первого администратора

В файле `.env` (он уже создан в папке проекта) указаны логин и пароль для
первого админа. По умолчанию:

- **E-mail:** `admin@example.com`
- **Пароль:** `admin12345`

**Поменяйте их сейчас**, если хотите. Откройте файл `.env` в любом
текстовом редакторе (например, через Finder → нажать «Открыть с помощью» →
TextEdit) и поправьте строки `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`,
`SEED_ADMIN_NAME`. После этого вернитесь в Терминал и выполните:

```bash
npm run db:seed
```

Увидите сообщение `[seed] Создан админ: ...`. Готово — учётная запись
администратора в базе.

> Этот шаг можно повторять много раз, ничего страшного не будет: скрипт
> сначала проверяет, есть ли уже такой пользователь, и не создаёт
> дубликат.

## ШАГ 7. Запустить сайт

```bash
npm run dev
```

Через 5–10 секунд в Терминале появится строка:

```
   ▲ Next.js 14.2.18
   - Local:        http://localhost:3000

 ✓ Ready in 4s
```

Это значит, что сайт запущен. **Откройте браузер и перейдите по адресу**
<http://localhost:3000>.

> **Чтобы остановить сайт** — вернитесь в Терминал и нажмите `Ctrl + C`.

## ШАГ 8. Проверить, что всё работает

1. На главной странице нажмите **«Регистрация»** — создайте тестового
   пользователя (любой e-mail, например `test@test.ru`, и пароль не короче
   8 символов).
2. После регистрации вас перебросит на страницу **«Согласие на ОПД»** —
   поставьте флажок и нажмите «Подтвердить согласие».
3. Откроется **личный кабинет** — заполните все поля анкеты (ФИО, вуз,
   город и т. д.) и нажмите «Сохранить анкету». Под формой должна
   появиться зелёная надпись «Анкета сохранена».
4. Теперь зайдите под админом. Сверху справа нажмите **«Выйти»**, затем
   **«Войти»**, введите логин/пароль администратора (из `.env`).
5. В шапке появится красная ссылка **«Админ-панель»** — нажмите. Увидите
   таблицу с пользователями, метрики и возможность переключать роли.

Если все шаги отработали — сайт готов к работе локально.

## ШАГ 9. Загрузить проект на GitHub

Репозиторий уже подключён, осталось только отправить туда коммиты.

```bash
git push -u origin main
```

При первом запуске Терминал спросит логин и пароль GitHub:

- **Username:** ваш логин GitHub (`AmatDgan`)
- **Password:** **не пароль от аккаунта**, а **Personal Access Token**.

Если токена ещё нет:

1. Открыть <https://github.com/settings/tokens>.
2. Нажать **Generate new token (classic)**.
3. В поле «Note» написать что-то вроде «DKP_NSU local push».
4. Поставить галочку напротив **repo** (полные права на репозитории).
5. Нажать **Generate token** внизу страницы.
6. Скопировать длинную строку, которая появится (она показывается **один
   раз**, второй раз её посмотреть нельзя).
7. Вернуться в Терминал и вставить эту строку вместо пароля.

После `git push` Терминал покажет:

```
* [new branch]      main -> main
Branch 'main' set up to track remote branch 'main' from 'origin'.
```

Откройте <https://github.com/AmatDgan/DKP_NSU> — должны увидеть 9
коммитов и все файлы проекта.

> macOS обычно запоминает токен в Keychain после первого ввода. Второй раз
> вводить не придётся.

## Что лежит в .env, и почему его нет на GitHub

Файл `.env` содержит секреты (пароль админа, секретный ключ для подписи
сессий). Он **никогда не попадает в репозиторий** — это прописано в
`.gitignore`. На другом компьютере (или на боевом сервере) `.env` нужно
будет создать заново — образец лежит рядом в `.env.example`.

## Если что-то не работает

| Проблема                                          | Что делать                                                                                                                                        |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `command not found: npm`                          | Не установлен Node.js — вернитесь к **ШАГу 1**.                                                                                                   |
| `command not found: npx`                          | Старая версия Node — переустановите свежий LTS с nodejs.org.                                                                                      |
| `EACCES: permission denied`                       | Терминал открыт не в той папке. Перепроверьте `pwd` — он должен показать путь, заканчивающийся на `Проект ЦБ`.                                    |
| `Error: P1003: Database ... does not exist`       | Не выполнен **ШАГ 5**. Запустите `npx prisma db push`.                                                                                            |
| `Invalid username or password` при `git push`     | Введён обычный пароль GitHub вместо Personal Access Token. Сгенерируйте токен по инструкции из **ШАГа 9** и используйте его как пароль.           |
| Порт 3000 уже занят                               | Завершите старый процесс: `lsof -ti:3000 \| xargs kill -9` и запустите `npm run dev` снова.                                                       |
| Хочется удалить тестовых пользователей            | `npx prisma studio` → откроется браузер с таблицами → таблица `User` → выделите строки → Delete.                                                  |
| Забыли пароль админа                              | Откройте `.env`, поправьте `SEED_ADMIN_*`, выполните `npm run db:seed` ещё раз — он повысит пользователя до админа (или создаст нового).          |
| Хочется откатиться к одному из этапов разработки  | `git log --oneline` — посмотреть список этапов, потом `git checkout <первые 7 символов хеша>` для просмотра или `git reset --hard <хеш>` для отката. |

## Дальнейшие шаги (когда дойдёте до боевого запуска)

1. **Сменить базу с SQLite на PostgreSQL.** В `prisma/schema.prisma`
   заменить `provider = "sqlite"` на `"postgresql"` и в `.env` поправить
   `DATABASE_URL` (например, `postgresql://user:pass@host:5432/db`).
2. **Сгенерировать новый `AUTH_SECRET`** командой
   `openssl rand -base64 32` и положить в боевой `.env`.
3. **Сменить `AUTH_URL`** на реальный домен (например,
   `https://dkp.nsu.ru`).
4. **Развернуть.** Самый простой вариант — Vercel: импортировать репозиторий
   <https://github.com/AmatDgan/DKP_NSU>, добавить переменные окружения в
   настройках проекта Vercel и нажать Deploy.

## Краткая шпаргалка (для повторных запусков)

После первой настройки чтобы просто открыть сайт ещё раз, нужно только:

```bash
cd "/Users/amattolkocokov/Documents/Claude/Projects/Проект ЦБ"
npm run dev
```

И открыть в браузере <http://localhost:3000>.

Если поменяли модели в `prisma/schema.prisma` — после изменения выполните
`npx prisma db push`.

Если добавили или поправили код — изменения **подхватываются автоматически**,
пока запущен `npm run dev`. Перезапускать ничего не нужно.
