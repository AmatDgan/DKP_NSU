# Деплой перехода на MySQL — пошагово

Коротко: на компьютере отправляем изменения через **GitHub Desktop**, на сервере
забираем их `git pull`, создаём таблицы через **phpMyAdmin**, пересобираем сайт и
заводим админа. Делай строго по порядку, шаги отмечай галочками.

Почему мы это делаем: старый движок Prisma (на Rust) падал на сервере из‑за
устаревшего системного OpenSSL 1.0.2. Я переписал проект на новый клиент Prisma 6
без Rust — он ходит в MySQL через JS‑драйвер и не падает. Это уже проверено.

---

## Шаг 1. Отправить изменения с компьютера (GitHub Desktop)

1. Открой **GitHub Desktop**. Слева во вкладке **Changes** ты увидишь список
   изменённых файлов. Убедись, что там есть в том числе:
   - `package.json`
   - `prisma/schema.prisma`
   - `prisma/seed.ts`
   - `prisma/init.sql` (новый файл)
   - `src/lib/prisma.ts`
   - `src/lib/auth.ts`
   - `src/lib/auth.config.ts` (новый файл)
   - `src/middleware.ts`
   - `next.config.mjs`
   - папка `src/generated/prisma/` (много новых файлов — это нормально, нужно
     закоммитить ВСЕ)
   - `.env.production.example`

   > Файл `.env` (без `.example`) в списке появляться НЕ должен — он скрыт от git
   > и хранит секреты. Так и нужно.

2. Внизу в поле **Summary** впиши короткое описание, например:
   `Переход на MySQL: Prisma 6 без Rust-движка`

3. Нажми синюю кнопку **Commit to main**.

4. Сверху нажми **Push origin** — изменения уйдут на GitHub.

---

## Шаг 2. Забрать изменения на сервере (SSH)

Зайди на сервер по SSH (как раньше) и перейди в папку проекта. Затем:

```bash
cd ~/dkpnsu.ru            # папка проекта на сервере (поправь путь, если другой)
git pull
```

Должно написать, что файлы обновлены (`Fast-forward`, список изменённых файлов).

---

## Шаг 3. Проверить файл `.env` на сервере

В папке проекта на сервере должен быть файл `.env` с MySQL‑подключением.
Открой его на просмотр:

```bash
cat .env
```

Убедись, что строка `DATABASE_URL` указывает на MySQL **через сокет**. Должна быть
такого вида (подставь свои логин/пароль/имя базы из панели хостинга):

```
DATABASE_URL="mysql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@localhost/ИМЯ_БАЗЫ?socket=/var/lib/mysql/mysql.sock"
```

> Важно: часть `?socket=/var/lib/mysql/mysql.sock` обязательна. Без неё драйвер
> попробует подключиться по сети и не сможет. Точный путь к сокету можно
> посмотреть в панели Sprinthost (раздел MySQL), но обычно он именно такой.

Также проверь, что заданы:

```
AUTH_SECRET="...длинная случайная строка..."
AUTH_URL="https://dkpnsu.ru"
SEED_ADMIN_EMAIL="...твой e-mail для входа в админку..."
SEED_ADMIN_PASSWORD="...надёжный пароль не короче 12 символов..."
```

Если чего‑то не хватает — допиши (редактор: `nano .env`, сохранить `Ctrl+O`,
выйти `Ctrl+X`).

## Шаг 4. Создать таблицы в MySQL через phpMyAdmin

Таблицы создаём напрямую SQL‑файлом — командой `prisma db push` пользоваться
НЕЛЬЗЯ (её движок тоже падает на старом OpenSSL).

1. Открой в браузере **phpMyAdmin** (ссылка в панели Sprinthost, раздел «Базы данных»).
2. Слева выбери свою базу (ту, что в `DATABASE_URL`).
3. Сверху открой вкладку **Импорт**.
4. Нажми **Выберите файл** и укажи файл из проекта: `prisma/init.sql`.
   (Если открываешь phpMyAdmin с другого компьютера — сначала скачай `prisma/init.sql`
   с сервера или возьми из папки проекта на своём ПК, он одинаковый.)
5. Прокрути вниз и нажми **Импорт** (или **Вперёд**).

Должно появиться «Импорт успешно завершён». Слева в списке базы появятся 4 таблицы:
`User`, `Profile`, `Application`, `SupportMessage`.

> Файл безопасно импортировать повторно — таблицы создаются только если их ещё нет,
> существующие данные не трогаются.

---

## Шаг 5. Установить зависимости и пересобрать сайт (SSH)

В папке проекта на сервере выполни по очереди:

```bash
npm22 install
npm22 run build
```

- `npm22 install` поставит новые версии библиотек (Prisma 6, драйвер mariadb).
  Если в процессе мелькнёт предупреждение про `prisma generate` — это не страшно,
  готовый клиент уже лежит в репозитории, установка всё равно завершится успешно.
- `npm22 run build` соберёт сайт. В конце должна появиться таблица со списком
  страниц и строка `Middleware`. Это значит, сборка прошла.

---

## Шаг 6. Создать администратора

Когда таблицы созданы и сборка прошла, заведи учётку админа:

```bash
npm22 run db:seed
```

Скрипт возьмёт `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD` из `.env` и создаст
администратора. Должно написать: `Создан админ: ...` (или «обновлён», если уже был).

---

## Шаг 7. Перезапустить приложение

Чтобы сервер подхватил новый код:

```bash
mkdir -p tmp && touch tmp/restart.txt
```

(Либо нажми кнопку перезапуска приложения в панели Sprinthost.)

---

## Шаг 8. Проверить вход

1. Открой `https://dkpnsu.ru/auth/login`.
2. Введи e‑mail и пароль администратора (из `.env`).
3. После входа открой `https://dkpnsu.ru/admin` — должна открыться админка.
4. Заодно проверь регистрацию обычного участника и личный кабинет
   `https://dkpnsu.ru/dashboard`.

Если вход проходит и админка открывается — переход на MySQL завершён, можно
открывать регистрацию.

---

## Если что‑то пошло не так

- **Сайт отдаёт 500 после деплоя.** Посмотри лог: в папке проекта
  `tail -n 50 ~/dkpnsu.ru/log/*.log` (или раздел «Логи» в панели). Чаще всего это
  опечатка в `DATABASE_URL` (проверь `?socket=...`) или не созданы таблицы (Шаг 4).
- **`npm22 run db:seed` пишет про подключение к базе.** Значит `.env` не видит
  MySQL — проверь `DATABASE_URL` и что таблицы созданы.
- **`git pull` ругается на локальные изменения на сервере.** Напиши мне — поправлю,
  не делай `git reset` наугад.

Любой шаг, где затык, — пришли мне вывод из терминала, разберём.
