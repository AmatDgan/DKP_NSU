# Развёртывание сайта на reg.ru (ISPmanager)

Пошаговая инструкция, как выложить сайт в интернет на вашем хостинге reg.ru.
Рассчитана на то, что вы делаете это впервые. Команды можно копировать целиком.

---

## Сначала главное — что мы выкладываем

Ваш сайт — это **приложение** (Next.js), а не просто набор HTML-страниц.
У него есть регистрация участников, личные кабинеты, админ-панель и база данных.
Поэтому его нельзя просто «закинуть файлы» в папку — на сервере должен работать
**Node.js**. Хорошая новость: ваш ISPmanager это умеет.

Два важных пояснения:

- **База данных.** Сайт использует встроенную базу SQLite — это просто файл на
  сервере. Отдельную СУБД настраивать не нужно. **MySQL, который вам выдали в
  доступах, для этого сайта не требуется** — можете его не трогать.
- **Безопасность.** Пароли, которые вы прислали на скриншоте, теперь «засветились».
  После того как всё заработает, рекомендую сменить пароль хостинга/SSH в личном
  кабинете reg.ru.

---

## Шаг 0. Отправьте последний код на GitHub

Я внёс финальные правки для продакшена. На **вашем компьютере** в папке проекта
выполните:

```bash
git push
```

(GitHub попросит логин и токен — введите один раз.)
Без этого шага сервер скачает старую версию.

---

## Шаг 1. Привяжите домен к хостингу

В личном кабинете reg.ru → раздел **«Домены»** → у вашего домена пропишите
**DNS-серверы хостинга** (reg.ru обычно подставляет их сам, если домен и хостинг
в одном аккаунте). Либо вручную создайте A-записи:

| Запись | Значение        |
|--------|-----------------|
| `@`    | `31.31.196.97`  |
| `www`  | `31.31.196.97`  |

Обновление DNS может занять от 15 минут до нескольких часов.

---

## Шаг 2. Проверьте, что доступен Node.js

Войдите в панель: **https://server206.hosting.reg.ru:1500/**
(логин и пароль — из блока «Доступ в панель управления»).

В меню должен быть раздел, связанный с **Node.js** (или он появляется при создании
сайта как «Обработчик»). Если Node.js на вашем тарифе недоступен — напишите в
поддержку reg.ru: *«Прошу включить поддержку Node.js для моего хостинга»*. Это
бесплатно на тарифах, где Node.js поддерживается.

---

## Шаг 3. Создайте сайт с обработчиком Node.js

В панели: **Сайты → Создать сайт**.

- **Доменное имя** — ваш домен.
- **Обработчик** — выберите **Node.js**.
- **Способ подключения** — **Порт**.
- **Версия Node.js** — **20** (или любая ≥ 18.17).

Сохраните. Запомните **корневую директорию сайта** (её показывает панель,
например `/var/www/u3534888/data/www/ваш-домен`).

---

## Шаг 4. Загрузите код с GitHub

Откройте **Shell-клиент** (в меню сайта — кнопка «…») или подключитесь по SSH.
Перейдите в корневую директорию сайта и скачайте проект:

```bash
cd ~/sites/ВАШ-ДОМЕН        # или путь, который показала панель
rm -rf * .[!.]*             # очистить пустую папку от заглушек
git clone https://github.com/AmatDgan/DKP_NSU.git .
```

Точка в конце `git clone ... .` обязательна — она кладёт файлы прямо в эту папку.

---

## Шаг 5. Создайте файл настроек `.env`

```bash
cp .env.production.example .env
nano .env
```

Заполните значения (остальное не трогайте):

- `AUTH_SECRET` — длинная случайная строка. Сгенерируйте отдельной командой
  `openssl rand -base64 32` и вставьте результат.
- `AUTH_URL` — `https://ВАШ-ДОМЕН` (точно ваш домен, без слэша на конце).
- `SEED_ADMIN_EMAIL` — ваша почта (это будущий вход в админку).
- `SEED_ADMIN_PASSWORD` — надёжный пароль (≥ 12 символов).

Сохранить в nano: `Ctrl+O`, `Enter`, затем `Ctrl+X`.

---

## Шаг 6. Установите и соберите проект

Выполните по очереди:

```bash
npm install            # установка зависимостей (несколько минут)
npx prisma db push     # создаёт базу данных и таблицы
npm run db:seed        # создаёт администратора из .env
npm run build          # сборка боевой версии
```

Если `npm run build` упадёт с ошибкой про память — выполните
`NODE_OPTIONS=--max-old-space-size=1024 npm run build` или напишите в поддержку
reg.ru с просьбой поднять лимит памяти.

---

## Шаг 7. Запустите сайт

В панели, в меню сайта (кнопка «…»), нажмите **«Перезапустить (Node.js)»**.
Иконка Node.js должна стать **зелёной** — значит, приложение работает.

---

## Шаг 8. Включите HTTPS (обязательно)

Вход в личные кабинеты работает только по защищённому соединению.

В панели: **Сайты → ваш сайт → SSL-сертификаты → Let's Encrypt**, выпустите
бесплатный сертификат для домена и `www`. Затем включите
**перенаправление с HTTP на HTTPS**.

Убедитесь, что в `.env` значение `AUTH_URL` начинается с `https://`, и ещё раз
нажмите **«Перезапустить (Node.js)»**.

---

## Шаг 9. Проверьте, что всё работает

Откройте `https://ВАШ-ДОМЕН`:

- главная страница — лендинг программы;
- зарегистрируйте тестового участника и войдите в личный кабинет;
- войдите в админку по адресу `https://ВАШ-ДОМЕН/admin` с данными `SEED_ADMIN_*`;
- проверьте, что в секциях открываются PDF-материалы.

---

## Как обновлять сайт в будущем

Когда внесёте изменения и отправите их на GitHub (`git push`), на сервере:

```bash
cd ~/sites/ВАШ-ДОМЕН
git pull
npm install            # только если менялись зависимости
npm run build
```

и нажмите **«Перезапустить (Node.js)»** в панели.

---

## Если что-то не работает

- **Node.js не зелёный / падает при старте.** Откройте Shell и выполните
  `npm run build`, затем снова «Перезапустить (Node.js)». Посмотрите логи в
  панели (кнопка «Логи» у сайта).
- **502 Bad Gateway.** Приложение не запустилось — перезапустите Node.js,
  проверьте логи.
- **Вход не срабатывает / выкидывает обратно.** Проверьте, что SSL включён и
  `AUTH_URL` в `.env` — это ваш домен с `https://`. После правки `.env` всегда
  перезапускайте Node.js.
- **«disk I/O error» от базы.** Убедитесь, что файл `prisma/dev.db` и папка
  `prisma/` доступны на запись пользователю сайта.

## Замечание про «правильную» базу (на будущее)

Сейчас сайт работает на SQLite — этого с запасом хватает для регистрации
участников конференции, и это самый простой и надёжный вариант для старта.
Если в будущем понадобится перевести сайт на выданный вам MySQL, это отдельная
доработка кода (в проекте есть SQLite-специфичные запросы) — напишите мне, и я
помогу её сделать. Для запуска сейчас этого делать не нужно.
